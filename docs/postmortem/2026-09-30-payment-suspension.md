# 2026-09-30 契約の利用停止によるサイト停止

| 項目 | 内容 |
|---|---|
| 発生 | 2026-09-30 08:31（Better Stackの検知時刻） |
| 復旧 | 2026-09-30 11:52（Better Stackの自動検知） |
| 継続時間 | 約3時間20分（Better Stackの記録で3時間18分） |
| 分類 | 契約・支払いによる停止 |
| 検知方法 | 監視アラート（Better Stack） |

## 概要

お試し期間終了時のカード決済エラーで契約が利用停止となり、9/30 8:31〜11:52、サイトが外部から応答しなくなった。

## 影響

- サイトに約3時間20分（Better Stackの記録で3時間18分）の間、外部からアクセスできなくなった
- バックアップは毎日成功しており、データ損失はゼロ
- ステータスページではUTC基準で日付を区切るため、9/29と9/30の2日に分かれて表示されるが、同一の停止である

## 時系列

| 日時 | 出来事 |
|---|---|
| 9/25 | お試し期間終了。カード決済エラー |
| 9/26 09:30 | さくらから決済エラーの通知メール（1通目） |
| 9/26〜9/29 | 同様のメールが毎日届く（計4通）。いずれも未確認。サイトは正常稼働、バックアップも毎日成功 |
| 9/30 08:31 | Better Stackが検知し、学校のアドレスに通知 |
| 9/30 11:10 | 通知に気づく |
| 9/30 11:13 | サイトの応答がないことを確認 |
| 9/30 11:25 | コントロールパネルで「利用停止中」「帯域制限中」を確認 |
| 9/30 11:32 | 決済エラーのメールを発見 |
| 9/30 11:39 | カード変更・決済 |
| 9/30 11:52 | Better Stackが復旧を自動検知 |

## どう気づいたか

Better Stackの監視アラートのメールで気づいた。

| 通知 | 届いた先 | 気づくまで |
|---|---|---|
| Better Stackの障害通知 | 学校のアドレス | 2時間40分 |
| さくらの決済エラー通知 | 個人のアドレス | 約4日間（1通目の9/26 09:30から。計4通、すべて未確認） |

気づくのが遅れた理由

重要な通知がメールでしか届かず、そのメールを日常的に確認する仕組みがなかった。

- Better Stackの通知は、普段見ない学校のアドレスに届く設定だった
- さくらの通知は個人のアドレスに届いていたが、個人のアドレスも含め、メールを日常的に確認する運用になっていなかった
## 調査でやったこと

1. サイトを開くとタイムアウトし、応答がないことを確認
2. Better Stackのメールから別のアカウントの画面に飛んでしまい、一時的に混乱した
3. VPSが停止している可能性を疑い、さくらのコントロールパネルで確認 → 稼働中だったため否定
4. 過負荷を疑い、CPU・ディスクなどのグラフを確認 → 異常がなかったため否定
5. 過去のメールを遡り、さくらインターネットからの決済エラーのメールを確認して原因を特定

## 原因

- **直接の原因**：カードの利用枠の上限で、お試し期間終了時の決済が通らなかった
- **背景の原因**：重要な通知の届け先がメールだけで、そのメールを日常的に確認する仕組みがなかったため、決済エラーの通知が約4日間把握されなかった

## 運が良かったこと

- 支払期限の前に気づいて、データが消える前に復旧できた
- 停止時間が毎晩21:30のバックアップの時間とたまたま重ならなかった

## 再発防止

| 対策 | 期限 | 状態 |
|---|---|---|
| Better Stackの通知先をSlackに変更（無料プランではDiscordへ直接通知できないため） | 10/4 | 未着手 |
| さくら等の契約・請求メールの受信先を1つのアドレスに集約し、スマホで受信時に通知が出るよう設定する | 10/4 | 未着手 |
| カード有効期限・ドメイン更新日をカレンダーに登録 | 10/4 | 未着手 |
| バックアップ失敗の検知を実装（Uptime KumaのPush監視） | 10/31 | 未着手。Ansible化の後に実施 |

※ バックアップ失敗の検知を実装するまでの間は、バックアップだけが失敗した場合に検知できない。

## 学んだこと

- 今回は初のインシデントで、AIにサポートしてもらいながらの復旧だった
- サイト→VPS→リソース→契約と、外側から順に原因を絞り込む手順を体験した
- 技術が正しくても、技術以外の部分でサーバーが停止することがある
- 監視の通知を把握する仕組みがなければ気づかない
